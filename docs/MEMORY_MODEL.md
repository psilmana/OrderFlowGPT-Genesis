# Memory Model

The Memory Model defines how Genesis preserves learning over time.

Memory is where lessons, experiences, corrections, outcomes, and reflections accumulate until durable knowledge emerges.

## Memory Purpose

Memory allows Genesis to:

- Remember Fabio's lessons.
- Recall prior market experiences.
- Compare current observations with past cases.
- Preserve mistakes and corrections.
- Track how understanding changes over time.
- Convert repeated reflected experiences into knowledge.

## Memory Contents

Memory may contain:

- Lesson records.
- Experience records.
- Teacher corrections.
- Student reasoning attempts.
- Reflection notes.
- Market state examples.
- Location examples.
- Aggression examples.
- Risk examples.
- Management examples.
- Knowledge objects derived from repeated experience.

## Memory Organisation

Memory should be organised around Fabio's hierarchy:

1. Market State.
2. Location.
3. Aggression.
4. Risk.
5. Management.
6. Reflection.

This structure keeps memory aligned with discretionary reasoning rather than raw perception artifacts.

## Memory and Existing Modules

Existing Memory and Dataset capabilities must remain part of the system. GLA v1 does not remove, rename, or break them. Instead, it documents their future architectural role as support for apprenticeship learning.

## Memory Quality

A memory item is more valuable when it includes:

- The original observation.
- The reasoning path.
- Fabio's explanation or correction.
- The outcome.
- The reflection.
- Links to related experiences.
